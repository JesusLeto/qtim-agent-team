# Codex second-opinion — протокол консультации

> Скил плагина qtim; доступен любой роли через `Skill`. Codex — модель другого семейства,
> поэтому ловит слепые зоны, которые одна модель пропускает систематически.
>
> Здесь только **consult**: read-only второе мнение. Полоса, где Codex пишет код
> (execution lane), каналы вызова через слэш-команды и оркестрация dual-adversary —
> зона team-lead'а, в этот скил не входят и роли не нужны.

## Принципы

1. **Advisory, не authoritative.** Codex даёт input — решение остаётся за тобой.
2. **Инвариант побеждает.** Совет против доменного инварианта проекта (charter + `memory/`) —
   отбрасывается с пометкой почему. Codex не знает тонкостей модели доступа и домена.
3. **Не доверяй слепо.** Каждый finding проверяй сам: открой `file:line`, проверь логику.
   Codex галлюцинирует ссылки и «находит» несуществующее.
4. **Read-only.** Всегда `-s read-only`. Codex консультирует, код не правит.
5. **Fail-soft.** Недоступен, таймаут, ненулевой exit → **эпик не блокируется**. Запиши
   `codex-consult skipped: <reason>` и работай на своём суждении.
6. **Только на gate-точке.** Максимальный reasoning стоит десятки секунд и денег — не дёргай
   на каждый шаг.

## Вызов

**Текст промпта не должен проходить через shell.** Консультация содержит diff, ADR или SQL —
в двойных кавычках shell выполнит `` `…` ``, `$(…)` и подставит `$VAR`: запрос испортится, а
чужой код выполнится. Это касается и `codex exec "<промпт>"`, и записи файла через
`printf '%s' "<промпт>"` — подстановка происходит **до** того, как текст куда-либо попал.

**Шаг 1 — приватный каталог.** Один вызов `Bash`, путь сразу печатается:

```bash
mktemp -d /tmp/codex-consult.XXXXXX
```

`mktemp -d` даёт права `drwx------`; просто положить файлы в `/tmp` нельзя — при обычном umask
они выйдут `-rw-r--r--`, а внутри лежит дифф политик доступа или биллинга и сырой вывод codex.

**Шаг 2 — промпт инструментом `Write`**, тогда shell текста не видит:

```
Write(file_path: "<путь из шага 1>/prompt.txt", content: "<промпт целиком>")
```

**Путь из шага 1 подставляй в последующие команды буквально, переменной не пользуйся:** каждый
вызов `Bash` — отдельный процесс, `d=$(mktemp -d)` из прошлого вызова в следующем уже пусто,
и путь схлопнется в `/out.md`.

```bash
codex exec -s read-only -C "$(git rev-parse --show-toplevel)" \
  -o <каталог>/out.md - < <каталог>/prompt.txt
```

Для ревью диффа есть встроенная подкоманда `review` — она сама скоупит изменения, склеивать
`git diff` в промпт не нужно. Две особенности, проверенные на codex-cli 0.144.4:

- **`-s` относится к `exec` и ставится до `review`** — у самой подкоманды флага песочницы нет,
  обратный порядок отвергается с ошибкой разбора;
- **флаг скоупа и свой текст ревью взаимоисключающи**: `--uncommitted` (как и `--base`,
  `--commit`) не сочетается с позиционным промптом, включая `-` для stdin —
  `error: the argument '--uncommitted' cannot be used with '[PROMPT]'`.

Отсюда выбор из двух, а не одна команда на все случаи:

```bash
# нужен автоскоуп диффа, хватает дефолтных инструкций ревью
codex exec -s read-only review --uncommitted -o <каталог>/review.md
# фича в отдельной ветке → --base <базовая ветка> вместо --uncommitted

# нужен свой фокус (щели доступа, presign TTL, money-пути) — обычный exec,
# скоуп опиши прямо в промпте: «смотри незакоммиченные изменения», «ветка против main»
codex exec -s read-only -C "$(git rev-parse --show-toplevel)" \
  -o <каталог>/out.md - < <каталог>/prompt.txt
```

- Прочитав вывод, убери каталог: `rm -r <каталог>`. Именно `rm -r`, а не `rm -rf` — последнее
  запрещено baseline-правилом `permissions.deny`, которое ставит сам `/qtim:setup`, и отказ
  посреди гейта легко принять за недоступность codex.
- **Money/security-режим:** добавь `--ephemeral` — иначе codex сохранит весь прогон, включая
  промпт с диффом, в `~/.codex/sessions/…/rollout-*.jsonl`, и чистка каталога этого не уберёт.
- Вызов долгий (десятки секунд — минуты): ставь таймаут `Bash` в 5-10 минут либо сразу понижай
  `model_reasoning_effort`. Оборвавшийся по таймауту вызов легко принять за недоступность codex
  и списать гейт в `skipped` на ложном негативе.
- `-C` из корня репо — Codex подхватит `AGENTS.md` и увидит `CLAUDE.md` / `memory/`.
- В промпт клади **конкретику**: diff, список файлов, текст ADR, конкретный инвариант.
  «Посмотри проект и скажи что не так» даёт generic-воду.
- Если максимальный reasoning избыточен — понизь: `-c model_reasoning_effort="high"`.

## Структура промпта

Codex промптится «как оператор» — компактные блоки в XML-тегах вместо сплошного текста:

```
<task>конкретная задача + скоуп (diff / файлы / текст ADR)</task>
<structured_output_contract>findings: file:line, severity P0..P3, конкретный fix</structured_output_contract>
<grounding_rules>каждое утверждение опирается на код, который реально открыл;
гипотеза помечается как гипотеза; не нашёл в контексте — так и скажи</grounding_rules>
```

`grounding_rules` обязателен — это прямое лекарство от галлюцинаций `file:line`. Для ревью
добавляй `dig_deeper_nudge`: second-order failures, пустые состояния, retries, rollback, гонки.
Роль задавай явно: «Ты independent <X>. НЕ редактируй код».

## Гейты по ролям

| Роль | Когда звать | Фокус промпта |
|---|---|---|
| `reviewer` | перед вердиктом APPROVED, после прохождения гейтов | щели модели доступа, безопасность сессии/токенов, presign/TTL, индексы на FK, N+1, zero-any, no-hardcode, привилегированные операции за гардом |
| `architect` | нетривиальный ADR (после своего черновика, до старта эпика); не на CONSULT-режим | упущенные open questions, угроза доменному инварианту, более простая альтернатива |
| `db` | security-critical миграция: новая политика доступа, триггер, helper-функция | щели видимости, идемпотентность, индексы на FK, корректность security-scoped контекста и search_path, каскады |
| `auditor` | старт проактивного security/perf-аудита | OWASP, щели доступа, N+1, отсутствие индексов, риски зависимостей, гипотезы для профайлинга |
| `product` | UX-аудит фичи после релиза | discoverability, пустые состояния, UI-копи целевой локали, navigation hints |

Повторный проход по дельте фиксов в той же фазе: consult — только если дельта сама задела зону
из строки роли, иначе `codex-consult: skipped (delta, low-risk)`. Фазу и дельту называет
team-lead в промпте задачи.

## Money- и security-critical — особый режим

Для биллинга, платёжных путей и модели доступа:

- Промпт формулируй как **нейтральный defect-review на корректность**, без «сломай / attack /
  exploit»: weaponized-формулировки в связке с деньгами режутся классификатором как false positive.
- Сырой вывод Codex **не ретранслируй** в тред целиком. Читай файл сам, в отчёт вноси только
  обезличенную выжимку: issue → impact → fix.

## Интеграция ответа

1. Прочитай файл вывода (для money/security — как выше, выжимкой), затем убери каталог:
   `rm -r <каталог>`.
2. Верифицируй каждый finding сам: открой `file:line`, проверь логику.
3. Конфликт «совет против инварианта» → инвариант; отброшенное — с причиной.
4. Подтверждённое — в работу по правилам своей роли (отчёт, баг-лог, задача исполнителю;
   нет `TaskCreate` в инструментах — состав задачи team-lead'у через `SendMessage`).
5. Одной строкой в отчёт: `codex-consult: N findings, M подтверждено, K отброшено
   (конфликт с инвариантом X)` — либо `skipped: <reason>`.

## Anti-patterns

- ❌ Применить совет без верификации.
- ❌ Заблокировать работу из-за недоступности Codex.
- ❌ Дать Codex право записи (`-s workspace-write`, `--dangerously-bypass-*`) — он консультант.
- ❌ Звать на каждый шаг вместо gate-точки.
- ❌ Промпт без скоупа.
- ❌ Weaponized-формулировки на money/security-коде.
