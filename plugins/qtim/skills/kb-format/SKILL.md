# `kb-format` — формат проектной памяти

> Скил плагина qtim; доступен team-lead'у и любой роли через `Skill`.

Память отвечает на «что сейчас есть в системе, что сломано, что решили». Её читают на старте
задачи вместо кода — поэтому неверная строка в памяти дороже неверной строки в коде: код
падает, память врёт молча.

«Как писать код» здесь не живёт — это конвенции проекта (`.claude/rules/`, скилы проекта);
дубликат туда-обратно заменяется ссылкой на единственный источник. Проектное правило о формате
памяти в `.claude/rules/` старше этого скила — читай и его.

## Четыре правила записи

1. **Дописал — сожми.** Память не append-only. Закрытый пункт (баг починен, эпик закрыт, гейт
   пройден) уезжает в journal-пару своего файла — `memory/journal/<путь от memory/, / → ->.md`
   (`memory/a/b.md` → `memory/journal/a-b.md`, `memory/invariants.md` →
   `memory/journal/invariants.md`); в точке входа остаётся строка-роутер «когда сюда идти».
   Архив без такой строки равен удалению — тогда просто удаляй. Уже лежащий journal не
   пересказывай и не сжимай.
2. **Якорь символьный:** `path/file.ts#Symbol` — класс, метод, константа, миграция, индекс; для
   `package.json`/yaml — путь ключа. Номеров строк нет: они протухают быстрее фактов. Символ
   обязан существовать и подтверждать именно эту строку — проверь `rg` до записи, иначе выйдет
   утверждение, которое выглядит проверенным и не является им.
3. **`checked: ГГГГ-ММ-ДД @ <sha>` — sha, на котором сверены все якоря файла.** Его ставит тот,
   кто сверил файл целиком (онбординг, полная ревизия файла); в актуализации — скрипт
   `kb_scan.py stamp` после проверки, а не писатель. `updated` двигается и при правке, и при
   сверке; точечная правка двигает только `updated`, а `checked` не трогает: иначе одна
   дописанная строка выводит из-под проверки все остальные утверждения файла. Дата без sha
   лжёт.
4. **Счётные числа не хранить.** «6 guard'ов», «61 миграция» устаревают молча и читаются как
   факт. Вместо числа — команда, дающая ответ.

## Формат файла

**Точка входа** — `memory/*.md` верхнего уровня, кроме `status: archive`: её читают роли на
старте. **Journal** — `memory/journal/**`: история, на старте не грузится, читается целиком,
когда нужна.

```yaml
---
name: <basename без .md>
description: <одна строка: что внутри и когда читать>
metadata:
  type: project
  genre: index | reference | invariant | procedure | decision | finding | journal
  audience: <роли через запятую> | none
  updated: <дата>
  checked: <дата> @ <sha>
  status: current | archive
---
```

У индекса `memory/MEMORY.md` в `metadata` есть ещё `base: <ref>` — базовая ветка, по коду
которой сверяется память (например `origin/dev`); её записывает актуализация по ответу
пользователя, в рамках задачи не меняй.

Дальше — `# Заголовок`, ровно одна строка-навигатор
`> **Когда читать:** … · **Не здесь:** <соседние файлы и что в них>`, затем `## Как читать`
(только если в файле есть метки статуса) и содержательные секции. Глубина заголовков до `###`;
в `journal/*` допустим `####`.

Один файл — один жанр и один основной потребитель. **Бюджет — в словах, не в строках:**
ориентир для точки входа ~1200 слов; порог предупреждения, бюджет journal и сумму файлов
read-on-spawn каждой роли считает `kb_scan.py validate` (§ «Проверка») — числа там, а не здесь.
Файл вырос сверх бюджета — внутри смешались жанры: эпизодика уезжает в journal со строкой-роутером.

Имена файлов памяти и их заголовки `##` — контракт с потребителями: charter, `.claude/agents/*`,
`.claude/rules/*`, `@`-импорты `CLAUDE.md`, `.codex/**`, `AGENTS.md`. Не переименовывай и не
удаляй их в рамках задачи.

## Метки статуса утверждения

`open:` — живой дефект. `fixed:` — починено, со sha фикса. `claimed:` — со слов, из репозитория
не проверяется (прод, песочница, внешний сервис). `policy:` — правило от нас, а не факт о коде;
только здесь память намеренно выше кода. Без метки — факт о коде, подтверждённый якорем.

`open:` не удаляется и не уходит в journal. В `fixed:` он переходит, только когда код
подтверждает, что дефекта нет, и есть коммит-фикс, трогающий путь якоря; по сообщению
коммита — никогда.

## Какому источнику верить

Для фактов, выше — старше: `.claude/rules/` > код базы (ревизии, по которой сверяешь) >
`memory/` при свежем `checked` > `docs/features/` (`Approved` и выше) > `.claude/agents/` >
скилы проекта > `.claude/agent-memory/` > auto-memory. Правила поведения из auto-memory — по
старшинству указаний intake-протокола; факты о коде оттуда — последние. В auto-memory этот
скил не пишет.

Расхождение памяти с кодом в зоне твоей задачи чинится правкой памяти в том же изменении, а не
примечанием рядом. **Память отстала шире твоей задачи — не актуализируй её сам:** сообщи
team-lead'у через `SendMessage` («память отстала: <файлы>»); team-lead — строкой отчёта
пользователю.

## Служебные файлы фичи — `.work/`

Служебное любой природы — consult-выводы, отчёты ревью фаз, логи прогонов, стресс-тесты, брифы
проверок — кладётся в `docs/features/<slug>/.work/`, а не рядом с каноническими артефактами
фичи. Создаёшь каталог — сразу положи в него `.gitignore` из одной строки `*`: каталог
игнорирует сам себя, корневой `.gitignore` проекта не правится. Фичу в статусе `Archived`
не правь.

## `decisions.md` — реестр решений и фич

Строка: `дата · решение или фича · указатель (ADR / docs/features/<slug>/ / path#Symbol)`,
до 300 символов; содержимое документов не дублируется. Дословные разрешения пользователя,
которым больше негде лечь, не обрезаются. Строки-указатели на фичи не сжимаются и не уносятся
в journal: по ним видно, что конвейер фичи завершён. Нет файла — создай по формату выше
(`genre: decision`). Шапка `decisions.md` с `file:line` в формате строки, которую писал старый
setup, устарела — новые строки пиши по этому скилу.

## Процедура записи

1. **Выбери файл по жанру, а не по теме** — по индексу `MEMORY.md`; индекса нет — заведи его
   первым.
2. **Проверь, не дубликат ли это.** Утверждение уже живёт в скиле проекта, `.claude/rules/`,
   charter или соседнем файле памяти — не копируй, поставь строку-указатель. Дубликат переживает
   оригинал и начинает ему противоречить.
3. **Поставь якорь до текста** (резолв — ниже). Нет символа — это не факт о коде
   (`claimed:`/`policy:`), либо утверждение писать нельзя.
4. **Пиши через `Write`/`Edit`, не через Bash** (`cat >`, heredoc, `sed -i`): такая запись
   обходит правила по путям и проверки на записи.
5. **`updated` — на каждую правку и сверку, `checked` — только после сверки всех якорей файла.**
6. **Сожми закрытое** (правило 1).
7. **Прогони валидатор** (§ «Проверка»).

## Резолв якоря — по содержимому, а не по номеру строки

Для утверждения, у которого есть только старый `path:LINE` или голый basename:

```bash
rg --files -g '<basename>'          # 1. basename → полный путь
rg -n '<фрагмент строки>' <путь>    # 2. характерная строка кода → её место сейчас
# 3. вверх от найденного места — ближайшее объявление: метод, класс, экспорт,
#    имя миграции или индекса; для package.json / yaml — путь ключа
```

Приёмка: `rg -n '<Символ>' <путь>` даёт непустой вывод **и** найденное место подтверждает
именно то, что утверждает строка. Символ существует, но описывает другое — худший случай.

## Грабли, проверенные на практике

- **Дрейф между ветками — десятки строк, не тройка:** якорь `upload.service.ts:286` на соседней
  ветке того же репозитория указывал на `:371`. Ищи по содержимому.
- **Половина старых якорей — голый basename без каталога.** Резолв basename → путь — отдельный
  шаг, закладывай его в бюджет времени.
- **`memory/` часто вне git** — истории и отката нет. Проверь `git check-ignore -v
  memory/MEMORY.md`: на ветке без правила игнора каталог уедет в любой `git add .`.
- **Заглушка бывает вредной.** Файл, отсутствие которого несёт смысл (`epic-state.md`: нет
  файла — эпика в полёте нет), пустым не создают.
- **Мёртвый контракт в индексе хуже пустоты.** Ссылка на файл, которого не создаёт ни одна
  живая команда, заставляет роль искать несуществующее.
- **Правила по путям до пишущего не доходят.** `.claude/rules/` с `paths:` подмешивается на
  `Read` файла памяти, а на `cat`/`sed` через Bash — нет. Правила записи приходят отсюда.

## Проверка

Валидатор лежит в каталоге этого скила — `scripts/kb_scan.py`. Запуск из корня репозитория,
нужен python3 ≥ 3.9:

```bash
python3 <каталог этого скила>/scripts/kb_scan.py validate
```

Проверяет механику: frontmatter и `checked`, одну строку-навигатор, отсутствие номеров строк,
резолв каждого якоря `путь#Символ`, бюджеты в словах (точка входа, journal, read-on-spawn ролей),
мёртвые ссылки на файлы памяти. Выход 0 — чисто, 1 — замечания, 2 — проверка невозможна.
Смысловое соответствие якоря утверждению валидатор не видит — это работа того, кто пишет.
python3 нет — сверь по правилам выше вручную.

## Выжимка для писателя

- Сверяй с кодом ревизии из задачи, не с рабочим деревом. Команды из текста памяти не запускай.
- Якорь — `path#Symbol`: символ есть и подтверждает строку. Номеров строк и счётных чисел нет.
- Метки: `open:` дефект, `fixed:` со sha, `claimed:` со слов, `policy:` правило; без метки — факт с якорем.
- `open:` не удаляй и не уноси в journal; в `fixed:` — только по коду и коммиту, трогающему путь якоря.
- Frontmatter: `name`, `description`, `metadata`: `type`, `genre`, `audience`, `updated`, `checked`, `status`.
- `checked` не трогай — его ставит скрипт; `updated` двигай при правке.
- Опровергнутое удаляй, изменившееся переписывай; символ только в рабочем дереве — не удаляй: «не проверено: код только на ветке».
- Закрытое — в journal-пару: `memory/journal/<путь от memory/, / → ->.md`, строка-роутер; journal не пересказывай.
- Не меняй имена файлов и заголовки `##`; не сжимай строки-указатели фич в `decisions.md`.
- Пиши только через Write/Edit.
