# Совместимость с рантаймом — журнал замеров

> Generic reference плагина. Читает **только team-lead** (и maintainer при апгрейде CLI).
> Здесь фактические наблюдения за поведением рантайма: что роль реально получает, чем
> отличается тиммейт от субагента, как это проверять. Действующие правила плагина — в CLAUDE.md,
> раздел «Чеклист при обновлении Claude Code»; тут только сырьё, на котором они стоят.
>
> Наблюдение стареет вместе с версией CLI. Прежде чем опираться на запись — сверь версию
> и при расхождении перезамерь по процедуре ниже.

## Процедура замера

Спавн роли и три действия подряд, потому что ни одного по отдельности не хватает:

1. попросить перечислить имена функций из блока `<functions>`;
2. попросить догрузить спорный инструмент через `ToolSearch`;
3. попросить **фактически вызвать** его и привести дословный результат или текст ошибки.

Список `<functions>` неполон: часть инструментов приходит отложенно — схемы не загружены, в
блоке их не видно, но `ToolSearch` подтягивает. Самоотчёт модели о собственном наборе тоже
ненадёжен: роль охотно рассуждает «инструмента нет» вместо вызова. Верен только п. 3.

**Тиммейта замеряют лишь в интерактивной сессии.** Headless (`claude -p`) команду при старте
заводит — каталог `~/.claude/teams/session-*` появляется, — но тиммейтов не поднимает: `Agent`
там всегда даёт субагента, сколько ни проси «подними teammate» (проверено дважды, в том числе
без указания инструмента в промпте).

**Признак тиммейта** — файл `~/.claude/teams/<session>/inboxes/<role>.json` на роль. Нет файла
— перед тобой субагент, и выводы про командный режим к нему неприменимы.

**Доставку контекста замеряют маркерами, не вопросом «что ты видишь».** В каждый канал
(CLAUDE.md, импортируемый файл, правило с `paths:` и без) кладётся уникальная строка вида
`MARKER-<КАНАЛ>-<N>`, роль поднимается **без `Read`** в `tools:` (иначе она найдёт маркер
в файле и замер ничего не покажет) и её просят перечислить видимые маркеры дословно. Для
ленивых каналов нужен второй зонд с `Read`: он отвечает до чтения, читает ровно один целевой
файл и отвечает снова.

## Замеры 2026-07-27 · CLI 2.1.199

Тиммейты в сессии с активной командой (флаг `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`):

| Конфигурация | Что получила роль |
|---|---|
| `haiku`, `Skill` **не** в `tools:` | плоский набор без `Skill`, без `ToolSearch`; `Task*` есть |
| `haiku`, `Skill` в `tools:` | `Skill` есть, вызов скила отработал; `Task*` прямо в `<functions>`; `ToolSearch` нет |
| `opus`, `Skill` в `tools:` | полный набор + отложенный (`Task*`, `Web*`, `Cron*`, `mcp__*`) через `ToolSearch`; `Agent`/`Artifact` сверх заявленного в `tools:` |

Роль-субагент в сессии **без** активной команды: `Bash`, `Read`, `Write`, `Edit`, `Skill`,
`SendMessage`; `Task*`, `Agent`, `ToolSearch`, `TodoWrite` отклонены с формулировкой
«exists but is not enabled in this context».

Поле `skills` во frontmatter предзагружает содержимое скила субагенту и **игнорируется**
у тиммейта — отсюда дублирование списка скилов в charter-таблице (setup 4.2).

## Замеры 2026-07-27 · CLI 2.1.220 — что доезжает до роли само

Полигон: проект с `CLAUDE.md` (маркер A1) → `@.claude/team-charter.md` (B2),
`.claude/rules/plain.md` без `paths:` (C3), `.claude/rules/scoped.md` с
`paths: ["src/**/*.ts"]` (D4), целевой `src/target.ts`. Зонды подняты из `.claude/agents/`.

| Канал | Что показал зонд |
|---|---|
| `CLAUDE.md` проекта | A1 в стартовом контексте роли |
| `@`-импорт из `CLAUDE.md` | B2 в стартовом контексте **дословно** — роль не делает для этого ничего |
| Правило без `paths:` | C3 в стартовом контексте |
| Правило с `paths:` | D4 на старте **нет**; появляется после `Read` совпавшего файла |
| То же правило, файл прочитан `Bash`-ом (`cat src/target.ts`) | D4 **не появляется** |

Подтверждает [`sub-agents#what-loads-at-startup`](https://code.claude.com/docs/en/sub-agents#what-loads-at-startup):
роль получает всю иерархию CLAUDE.md, включая project rules. Пропускают её только встроенные
`Explore` и `Plan` — то есть роль `explorer` (`subagent_type: Explore`) charter'а из импорта
**не увидит**, и это не чинится frontmatter'ом.

**Гейт `SubagentStop` с exit 2** (проверен на том же полигоне, скрипт со счётчиком срабатываний):
первый выход с кодом 2 роль не выпустил — она получила stderr и продолжила ход; второй вызов
с кодом 0 отпустил. Побочный эффект, ради которого замер и делался: **текст из stderr роль
принимает за новую задачу и теряет исходную** — зонд с заданием «ответь одним словом: привет»
вместо ответа начал разбираться с требованием гейта и объяснять, что не может его выполнить
(инструментов не выдано). Отсюда три правила для любого блокирующего гейта: проверять
**объективный признак** (файл существует / строка есть), а не верить отчёту роли; писать
в stderr выполнимое ролью действие; держать **счётчик попыток**, иначе роль, физически не
способная закрыть гейт, будет возвращаться в него до конца сессии.

**Не проверено:** тиммейт (headless команду заводит, но тиммейтов не поднимает — см. процедуру
выше), а с ним и события `TeammateIdle` / `TaskCompleted`. Заявлены в
[документации hooks](https://code.claude.com/docs/en/hooks) как блокируемые тем же exit 2,
но собственного замера под ними нет — на них ничего не строим без проверки.

## Ожидает замера — 1.14.0

Бюджет проверки и старшинство указаний (`intake-protocol.md`) доезжают до ролей только промптом
задачи и строкой шаблона спавна (`team-up.md`, шаг 4), а шаблоны `reviewer`/`testing` местами
требуют обратного (screenshots-gate как hard gate без вердикта «APPROVED при условии»; codex
обязателен на security/money-диффе; tester шлёт баг прямо исполнителю). На первом реальном
прогоне фичи проверить три вещи: reviewer не запрашивает оппонента на дельте вне зоны риска;
tester шлёт находку вне объёма team-lead'у, а не исполнителю; процессный пробел не даёт
NOT APPROVED. Итог записать сюда с версией CLI. Провал хоть одной — миграция шаблонов
`reviewer`/`testing`.

## Что из этого следует

- **`Skill` приходит роли тогда и только тогда, когда заявлен в её `tools:`** — от модели
  не зависит. Роль, ссылающаяся на скилы, обязана его перечислить.
- **`Task*` тиммейт получает всегда**, меняется лишь форма подачи; роль вне активной команды
  не получает их вовсе — отсюда fallback «нет `Task*` → состав задачи team-lead'у».
- **`tools:` — allowlist по документированному контракту, но не гарантия**: рантайм
  документированно отбрасывает заявленное у фонового субагента, а на `opus` 2.1.199 выдал
  незаявленные `Agent`/`Artifact`. Промпты не должны рассчитывать ни на то, что заявленное
  придёт, ни на то, что незаявленного не будет.
- **Есть два канала доставки, не требующих действий роли** — `@`-импорт из `CLAUDE.md` и
  `.claude/rules/`. Инструкция «прочитай charter на спавне» ими не заменяется, а страхуется:
  импорт может быть не настроен (setup дописывает его в 4.5, но `CLAUDE.md` — файл пользователя),
  а `explorer` его вообще не получает.
- **`paths:`-правило видит только тот, кто открыл файл через `Read`.** `git diff`, `cat` и
  прочий `Bash` его не поднимают — поэтому правило доезжает до исполнителя, который правит файл,
  но не заменяет чеклист роли, работающей по диффу (`reviewer`).
