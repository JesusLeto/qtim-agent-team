# Миграции и схема (acme)

- Миграция идемпотентна: `create ... if not exists`, `drop ... if exists` перед `create`,
  тела функций через `create or replace`. Второй прогон `supabase db push` не падает.
- Каждая корневая таблица несёт `workspace_id`: FK на `workspaces` + `on delete cascade`
  + индекс. Дочерние сущности (позиции смет, вложения) собственного `workspace_id` не имеют —
  доступ наследуют через проверку родителя.
- RLS включён на каждой новой таблице, политики — на все нужные операции, через
  `is_workspace_member()`. Клиентский фильтр видимость не заменяет.
- Helper-функции — `security definer` с фиксированным `search_path`; `stable` там, где предикат
  политики вызывается построчно.
- Индекс на каждый новый FK и на колонки в `where` / `order by`. Уникальность справочников —
  partial unique по нормализованной метке в рамках workspace.
- Деньги — `numeric(12,2)`, никогда float. Суммы смет считает БД (generated/trigger), не фронт.
- Схема сущностей и карта архитектуры в `memory/` обновляются в той же задаче, что и миграция.
